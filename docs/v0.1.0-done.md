# M1 done criteria, checked against tests

SPEC, Milestones, M1 Contain: "Done when". Each criterion is quoted exactly, with the tests (or files) that check it. `tools/releasecheck` (`TestEveryM1DoneCriterionIsCheckedAgainstATestThatExists`) fails if a criterion here drifts from the spec or a named test is renamed away. All of them run in `go test ./...` and `go -C tools test ./...`, which is what the `test` job in CI runs, except where a section says otherwise.

## The quickstart on Linux and macOS

> The quickstart test passes on Linux and macOS, word for word from the docs.

The test runs the shell lines of `docs/quickstart.md` verbatim, between its `quickstart:begin` and `quickstart:end` markers, against the binary under test, with only the machine faked (a shim `curl`, moved listeners, the credential typed on stdin). The `test` job in `.github/workflows/ci.yml` runs it on Linux and macOS (it skips on Windows and in containers).

- `e2e/quickstart_test.go::TestTheQuickstartRunsAsWritten`
- `e2e/docs_test.go`

## The official SDKs

> Pinned OpenAI and Anthropic SDKs (Python and Node, streaming and not) work through kman in e2e, with spend metered and visible per key.

The pinned OpenAI and Anthropic SDKs, Python and Node, through the real binary against a mock upstream: chat, responses and messages, streaming and not, and an upstream error. Each case checks that the upstream never saw the virtual key, and that the key's spend (today and this month) is what the response reported. The `sdk-e2e` job runs it with `KMAN_E2E_SDK=required`, so a missing SDK fails instead of skipping; the `test` job skips it where the SDKs are not installed. The docs' snippets run the same way.

- `e2e/sdk_test.go::TestOfficialSDKsWorkThroughKman`
- `e2e/spend_test.go::TestSpendIsMeteredAndShownBesideTheCaps`
- `e2e/sdkdocs_test.go::TestTheSDKDocSnippetsRunThroughKman`

## The regression tests

> Regression tests F1 (modelless bypass), F2 (errors charge caps), F3 (counters only for capped keys), F6 (unbounded maps), and F8 (rekey keeps the data key) are green.

F1 and F2 each have a unit, a gateway and an end-to-end test. F3 is read as SPEC §8 resolved it: spend is counted for every key, so a cap added later counts what was already spent. F6 holds the limiter's memory bounded under a flood of keys and addresses. F8 checks that a rekey keeps the data key's credentials and leaves nothing of the old one.

## The meter's properties and failures

> `meter` property tests hold under concurrency, and the kill-mid-stream and locked-store failure tests pass.

The property tests hold under concurrent requests (a key never passes its cap by more than one request; the books balance). A stream killed midway cuts the app and charges the whole reservation, in the gateway and end to end. A locked store fails capped keys closed and loses nothing, and a minute of failed flushes does the same through the gateway.

- `internal/meter/property_test.go::TestSpendNeverPassesACapByMoreThanOneRequest`
- `internal/meter/property_test.go::TestTheBooksBalanceWhateverIsGoingOn`
- `internal/gateway/spend_test.go::TestAStreamKilledMidwayChargesTheWholeReservation`
- `e2e/spend_test.go::TestAStreamKilledMidwayCutsTheAppAndChargesTheReservation`
- `internal/meter/sqlite_test.go::TestAStoreThatIsLockedFailsCappedKeysClosedAndLosesNothing`
- `internal/gateway/spend_test.go::TestAKeyWhoseSpendCannotBeRecordedForAMinuteIsRefusedWithStoreUnavailable`
